# H0001 FACA hypothesis and discriminating-experiment baseline

R094 owns explicit failure hypotheses and counter-hypotheses, supplied observation
likelihoods and next discriminating experiment selection. R098 reviews the
assumptions, ranking, proposed experiment and false causal-closure assertions.
This is a local analytical FACA baseline, not an actual root-cause proof.

## Inputs and decisions

Require distinct named failure mechanisms (including fixture/test-system versus
product alternatives), normalized positive priors and named observation records
with explicit likelihood under every hypothesis. The likelihoods are declared
uncalibrated model assumptions. Observation provenance is synthetic or supplied
unverified; neither labels nor a high posterior may certify a cause.

Require unique observation and source-record IDs plus an explicit conditional-
independence assumption for multiplied likelihood rows. Unknown/dependent rows
are unsupported in this first model; reject instead of silently double-counting.
This declared assumption remains unverified, not a statistical coverage claim.

Calculate normalized posterior in log space. Zero likelihood for every mechanism
is inconsistent evidence/model and must fail closed, not choose an arbitrary
cause. Detect missing hypotheses, duplicated observations and incomplete rows.
Report prior versus posterior ranking, eliminated hypotheses, unresolved model
coverage and counter-hypotheses. No threshold can set causal closure true.

Pin minimum leading model-posterior and leading-minus-runner-up margin as explicit
acceptance-policy inputs. They determine only whether a provisional model-based
next-action decision is supported. Ties and insufficient margins require further
discrimination; exact thresholds use a declared numerical resolution. Never call
this model-policy acceptance causal validation or posterior calibration.

Experiments declare ID, concrete intervention/control, observable outcomes,
outcome likelihoods under every hypothesis, positive relative cost and R0/R1
local-safe availability. Validate each hypothesis's outcome probabilities sum
to one. Rank available bounded experiments by expected entropy reduction per
cost, with deterministic explicit tie handling. An experiment with no separating
power cannot pretend to discriminate. This suggestion does not command hardware
or create physical results. Keep intervention and recurrence-validation gaps
visible even after a hypothetical discriminating outcome concentrates belief.

## Independent domain acceptance

R094 fixtures ask distinct failure questions: fixture versus amplifier noise,
same symptom with different observation provenance, conflicting observations,
insufficiently discriminating test, intervention selection, zero-probability
inconsistency and missing mechanism coverage. The oracles use manually worked
two/three-hypothesis probabilities and expected information gain, not method output.
R098 separately recomputes inference and expected experiment effects, challenging
posterior normalization, priors presented as evidence, ignored alternatives,
wrong intervention and root-cause/recurrence closure claims. Both seats retain
bounded L2; no automatic whole-role L3 or qualified Human approval.

## Actual company challenge

require a discriminating experiment. Revised input adds one explicitly synthetic
outcome of the selected experiment; hypothesis definitions, prior and policy
thresholds stay fixed. The declared local software acceptance is that the model
now supports a provisional next-action decision, never root-cause closure.
Execute real SQLite/workflow, qualified review, sealed input/report/reproduction
and source-derived Memory. Candidate inference remains clearly model-derived;
Memory is never substituted for observation or Evidence.

The revision must preserve every existing observation and experiment definition,
cost and availability exactly, appending precisely one observation. Bind the new
row to the first sealed execution's selected experiment ID/definition digest and
legal outcome ID; its complete likelihood vector must equal that sealed outcome
table. Require a new source-record ID, and preserve the declared conditional-
independence assumption. The aggregate revision-origin receipt binds the actual
first execution run and attempt, not an arbitrary external run reference.
Status revalidates this same append-only relationship from sealed first/second
inputs and selected output. Method-level fixture declarations alone do not prove
that this origin is real; the actual Challenge must establish that linkage.

Reject wrong experiment, forged outcome likelihood, replaced old observations,
changed experiment availability/cost, cross-attempt origin and repeated addition.
The existing top-level allowed_revision_fields check is necessary but insufficient
for an observation-array revision; this Challenge adds explicit semantic validation
before second execution and again during aggregate status verification.

Before coding, resolve numerical underflow, likelihood dependence, model coverage,
