# Definition of Company Done

AERIS 不可因為 repo 可以 clone、CLI 可以回話，就宣稱「整棟公司完工」。

## Gates

| Gate | Completion requirement |
|---|---|
| C0 Foundation | installer, runtime, tests, company manifest |
| C1 Governance | Constitution, authority, risk, approval, audit |
| C2 Organization | 100 role contracts + dynamic pod routing |
| C3 Knowledge | Skills, Methods, Standards, Memory/Graph |
| C4 Engineering | Speaker/Mic 2×6 vertical workflows |
| C5 Product | Product Chief playbooks across target products |
| C6 Trust | Evidence schema, G0–G5, reproducibility |
| C7 Tools | typed CAE/lab/DSP/firmware adapters |
| C8 Experience | Dashboard/Workspace/Services connected to live state |
| C9 Operations | backup, health, migration, failure recovery |
| C10 Portable Offline | clean-machine relocation + local AI without internet |
| C11 Business | service catalog, operating economics, release governance |

## Hard acceptance

- False-Done = 0 in release workflow.
- Unauthorized R3/R4 action = 0.
- Offline cloud-provider calls = 0.
- Core repository write by Codex = 0.
- Tier-A Evidence completeness = 100% target.
- Clean-machine relocation must be repeatable from an immutable package manifest.

Until all gates have executable evidence, status must be `IN_CONSTRUCTION`, not `COMPLETE`.
