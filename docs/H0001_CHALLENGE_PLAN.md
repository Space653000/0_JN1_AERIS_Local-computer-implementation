# H0001 company challenge execution seam

User H0001 section 12 is the parent specification. Preserve all existing role
and reviewer evidence gates. Scope of this incremental batch is three already
executable domains: Speaker power, microphone noise and TWS fit. The other five
required challenge families remain explicit software gaps, not External Gates.

## Contract and sequence

Author a tracked challenge registry with requirements, executor Skill/seat,
initial/revised synthetic inputs and independent expected dispositions. Discover
review qualification candidates from role/Skill manifests, not a fixed global
reviewer array. Use the actual matrix/status to record capability gaps. Missing
qualifications block by default; an explicit local preparation option runs each
missing bounded Role Acceptance suite and retains its actual sealed evidence.

Create one SQLite project for each challenge attempt. Execute both initial and
revised tasks through run_role, requiring initial DESIGN_REVISION_REQUIRED and
revised BOUNDED_REVIEW_ACCEPT. Revision changes model inputs only; no physical
countermeasure or product improvement is claimed. A no-op revision cannot pass.
Capture actual Pod selection, Method/source refs, numeric output, qualified
review bundles, counter-hypotheses, revisions and reports. Independently validate
both original and review seals and reproduce both numerical runs. Derive Memory
from these source events; Memory is never a substitute for Evidence.

Seal an aggregate challenge report containing its registry/source identity,
individual stage receipts, original/review/reproduction/report refs, Memory-only
event hashes and unresolved scope. PASS means this bounded integration challenge
passed; it never advances role L3, company maturity or physical verification.
Status must revalidate source bindings and referenced Evidence rather than trust
an editable latest-result label. No raw/local Evidence leaves .aeris.

## Tests and scope

Public seams: challenge inventory/run/status, actual ControlStore tasks,
run_role/Evidence/reproduction/Memory. Add tests for missing qualification, true
initial rejection and consequential revision, invalid challenge ID, no-op inputs,
tampered aggregate/child Evidence, stale source bindings, missing reports and
unsupported families. Preserve live six-route HTTP availability; use isolated
test state inside .aeris. No Core changes, remote push or main merge in this batch.

## Isolated review disposition

Both P1 findings accepted before implementation:

- Separate immutable requirements/acceptance limits from the explicit allowed
  design-input revision keys. Each challenge pins initial failing constraints,
  expected revision effect and independently authored numerical margin oracles.
  A no-op or a change to limits/requirements fails before execution. Synthetic
  revised observations are labeled a hypothetical analytical experiment, never
  an acquired measurement or physically proven countermeasure.
- Seal the full report/reproduction snapshots (and digests), not merely paths.
  Bind registry/source digest, attempt/project/task/workflow/stage/input digest,
  original execution run, review run and every qualification reference. Status
  validates all linkage and review_status, with wrong-attempt substitution and
  report-content tamper regressions. Mutable latest indices have no authority.

Post-implementation review at 26a24cb found an additional P1: matching mutable
task titles and report links is insufficient. The attempt/stage objective must
also match the original sealed execution context, with role/Skill/input bindings
and project Memory events referring to those same execution/review receipts.
A real two-attempt regression reproduced the relabelled transplant before repair.
Standards also found malformed JSON containers can escape the status response;
receipt shape validation and controlled failure are required. Both are accepted
as repair work, not dismissed because the original 277-test suite passed.
